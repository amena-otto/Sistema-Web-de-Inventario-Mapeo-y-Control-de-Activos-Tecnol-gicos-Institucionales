# Discrepancias conocidas entre documentación, código y SQL

Este registro recoge las diferencias detectadas durante la auditoría documental.
No implica cambios de código ni de base de datos: en cada caso se documenta el
comportamiento real y se indica si el asunto quedó resuelto en la documentación
o requiere atención posterior.

| # | Fuente anterior | Comportamiento verificado | Estado |
|---|---|---|---|
| 1 | README: «La impresión por lote queda como mejora posterior; actualmente se imprimen etiquetas individuales». | `src/pages/Equipos.tsx` implementa selección por fila y «Seleccionar esta página», con el botón «Vista previa e impresión masiva»; `EquipoQrDialog` recibe la lista y `crearDocumentoImpresion` genera hojas A4. | Documentado como funcional en [etiquetas QR](./modulos/etiquetas-qr.md). El README se actualizó. |
| 2 | README e informe de auditoría: «La revisión vencida se calcula sobre la última intervención de cada equipo activo, aunque esté completada». | La migración `013_cierre_mantenimientos.sql` define `equipos_revision_vencida()` e `indicadores_mantenimiento()` con `proxima_revision <= current_date` **y** `estado <> 'completado'` sobre equipos activos. `dashboardService.ts` aplica el mismo criterio. | Comportamiento real documentado en [mantenimientos](./modulos/mantenimientos.md) y [dashboard](./modulos/dashboard.md). Requiere que el lector ignore la redacción antigua conservada en el [informe histórico](./historico/auditoria-cierre-2026-10-25.md). |
| 3 | Documentación previa: el alta de mantenimientos podía registrarse en cualquier estado válido. | La RPC `registrar_mantenimiento` acepta `pendiente`, `en_proceso` o `completado` (esta última con diagnóstico, acciones y resultado obligatorios), pero `src/pages/Mantenimientos.tsx` fuerza `estado: 'pendiente'` y muestra un error si el formulario intenta `completado`. | Frontend más estricto que la base de datos; documentado en [mantenimientos](./modulos/mantenimientos.md). |
| 4 | README y documentación de base de datos: carga, reemplazo y eliminación de planos de piso, y marcadores en tiempo real desde Ubicaciones. | Las migraciones `005` y `012` crean la columna, el bucket y la tabla `marcadores_mapa`, pero no existe código en `src/` que use `plano_storage_path`, `planos-institucionales` ni `marcadores_mapa`. El [registro del 7 de noviembre](./operaciones/despliegue-eliminacion-equipos.md) también indica que `marcadores_mapa` no estaba presente en el entorno comprobado. | Capacidad de base de datos documentada como tal; la interfaz de planos/mapa **no está implementada** en este código. Pendiente de atención posterior. |
| 5 | Documentación anterior: «cinco disparadores de auditoría». | La migración `013` recrea cinco (`equipos`, `mantenimientos`, `componentes`, `relaciones_equipos`, `movimientos`) y la migración `020` añade `auditoria_equipo_areas_usuarias` para inserciones y borrados de vínculos. | Inventario actualizado en [seguridad, RLS y auditoría](./base-datos/03-seguridad-rls-y-auditoria.md). |
| 6 | `01-estructura-tablas.md`: lista de 15 tablas y secciones de columnas/índices pendientes de verificar. | Existen además `equipo_areas_usuarias` (020) y tablas de limpieza/constancia posteriores a la redacción original; el catálogo completo requiere consultar el esquema real, que no está incluido en el repositorio (`000_baseline.sql` pendiente). | Lista actualizada; la verificación de columnas e índices sigue marcada como pendiente y requiere acceso a un entorno enlazado. |
| 7 | `docs/etiquetas-qr.md`: «Nombre y código se dibujan consecutivamente». | `ajustarDatosEtiqueta` en `src/utils/etiquetasQr.ts` compone tres bloques: `NOMBRE`, `CÓDIGO` y `SERIE` (con «Sin serie» cuando no hay dato). | Documento migrado y corregido. |
| 8 | `docs/INTERFAZ_Y_EQUIPOS_COMPARTIDOS.md`: «Color azul real para acciones y mantenimiento». | El azul se usa en acciones de áreas usuarias, enlaces y estados; la identidad principal (barra lateral, foco y acento global en `src/index.css`) sigue en naranja. | Observación de interfaz, sin impacto funcional; se conserva el alcance original en el [registro histórico](./historico/entrega-equipos-compartidos.md). |
| 9 | `documentacion/operaciones/restauracion-backup.md` comenzaba con el fragmento aislado `Get-Service postgresql*#`. | Era un residuo de texto sin significado en el procedimiento. | Corregido al trasladar el documento a [respaldos y restauración local](./operaciones/respaldos-restauracion.md); el contenido operativo se conservó íntegro. |
| 10 | `documentacion/fase-11-pruebas-seguridad-respaldos.md` y el informe de cierre afirman que no hay ejecutor de pruebas de interfaz. | Sigue siendo cierto: `npm test` ejecuta pruebas de utilidades y PGlite, no pruebas de navegador. | Sin discrepancia; se aclara en el [plan de pruebas](./pruebas/plan-pruebas.md). |

Los informes bajo `historico/` conservan su redacción original, incluidas las
